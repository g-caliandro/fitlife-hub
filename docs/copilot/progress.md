**Deviations / conservative choices**
- Notifications are posted only for QUICK captures (chat captures are visible in the chat); answers from inbox/notification resume via the worker, answers in the chat run in place as before.
- No automatic retry of failed captures (network, keys, provider): FAILED + Error notification + Retry, to avoid duplicate calls and repeated notifications. No network constraint on the work (the spec wants an error, not a silent wait).
- Expedited work below Android 12 runs through WorkManager's own `SystemForegroundService` (already merged from the library before this phase; `getForegroundInfo` provided). No foreground service of ours.
- The capture activity is not exported; the shortcut targets it directly and the exported alias is the launcher entry. If the side key needs an exported target, use the alias.
- Notification permission is asked with the mic on the first quick capture and on first chat open; never insisted on. If denied, results are only in the inbox/chat.
- Audio files are deleted when the capture ends DONE/CANCELLED through the worker/chat run (transcript kept); a capture closed by discarding its last request or by Undo keeps its file (small leak, see gaps).
- Inbox badge = open requests + failed captures; the Home badge is still open requests only (spec wording).
- Chat voice requires the LLM key like text (composer disabled without it); a missing STT key shows as a retryable error.
- An empty inline reply re-posts the same question (needed to close Android's reply spinner); not a duplicate.
- STT request always sends `language` (Groq/Whisper style); OpenAI `gpt-transcribe` (which uses `languages`) is not special-cased.

**Known gaps / for the owner**
- `filesDir/captures/` audio is in Google auto-backup (decision 16 forbids touching backup rules): owner to decide whether to exclude it later.
- "Delete all data" does not remove captures, audio or chats (as in phases 2–3).
- Audio of captures undone or finished by discard is not deleted.
- Two answers to different requests of the same capture given at the same instant from different places can run two turns concurrently (writes stay idempotent).
- Silence threshold and max length (3 min) are first guesses.
- Still no `Log` calls in copilot code.
