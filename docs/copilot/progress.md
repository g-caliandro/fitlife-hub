**Deviations / conservative choices**
- Draft contents are a JSON payload column, not child tables (the task allowed child tables "as needed"; none are needed and this keeps drafts invisible to every plans query).
- One draft per capture: a second `propose_workout_plan` in the same message returns the draft already saved (Retry safety). A revision needs a new message and `replaces_draft_id`.
- Supersede happens only when the model passes `replaces_draft_id`; open drafts otherwise coexist. Delete removes the row (any status); Reject keeps it (REJECTED) so `get_workout_plan` can tell the model not to bring it back.
- A new goal's start is the **approval** day (deadline = approval + N weeks), not the proposal day. A new goal without weeks cannot be proposed (the tool requires them; 4 weeks is only a safety net).
- Exercises are matched by exact case-insensitive name (also hidden ones); no fuzzy matching. Unknown exercises without a category are a tool error; with a category they are created as custom exercises at Approve (never at proposal).
- `suggest_meal` takes grams only (no servings/measures) and is READ (writes nothing); it is also offered to quick captures (harmless, no chat-only flag). Log as meal uses the time of the tap (today, now), not the suggestion date. Values come from the food row at write time: if the user edits the food between suggestion and tap, the diary gets the edited values (not tested; the snapshot in the card is used only for foods not yet in the DB).
- After Undo, a suggestion cannot be logged again from the same card (same rule as "never redone").
- Disliked foods are enforced only for keys `disliked_foods` / `cibi_non_graditi` / `alimenti_non_graditi` (comma-separated, every word of the disliked food must appear in the name); other preferences are only in the prompt.
- Memory cap: 30 facts / 200 characters / 1,500 prompt characters; a full memory refuses new keys instead of evicting old ones.
- "Delete all data" keeps the user memory (like chats and household measures); a JSON import replaces it only when the file has `userMemory`.
- Plan drafts are not exported (decision 7 does not list them).
- Deleting a thread discards its open requests and removes its messages; captures, the diary and drafts stay.
- Threads list shows CHAT and QUICK threads together (icon tells them apart); the per-thread badge counts open requests linked to that thread.
